## What it means

A call to an overloaded .NET method matches more than one of its overloads equally well. .NET methods often come in several versions, called overloads, that take different parameter types, and Taipan picks the one whose parameters fit the arguments best, as C# does. When two fit equally well and neither is better, the compiler can't choose, so it reports both. This usually happens when a Taipan `int` has to become one of two other .NET integer types, such as `uint` and `ulong`, and the method has no version taking `long`, which is what an `int` is in .NET.

## How to fix it

<!-- no help: Taipan has no way to pick an overload yet (§13.5); the fix is another method -->

Here, `BitOperations.PopCount` counts the bits set in a number, and has overloads for `uint` and `ulong`, but not `long`:

```taipan
from dotnet.System.Numerics import BitOperations

print(BitOperations.PopCount(5))
```

```error
main.tpn:3:21: error TP0232: ambiguous call to 'BitOperations.PopCount': it could be 'PopCount(uint)' or 'PopCount(ulong)'
```

Call a method whose parameter is a `long`, so that one version fits exactly. `Int64.PopCount` does the same for a `long`:

```taipan
from dotnet.System import Int64

print(Int64.PopCount(5))
```

```output
2
```

[Overloads, generics and delegates](../../guides/dotnet/#overloads-generics-and-delegates) has how an overload is chosen.
