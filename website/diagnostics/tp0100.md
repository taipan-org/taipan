## What it means

The code isn't arranged the way the language's grammar allows. The compiler read the file up to some point, expected one thing next (a `:`, a closing bracket, an expression) and found something else. The message says what it expected and what it found, and points at the spot where it found it. The real mistake is often just before that spot, or on the line above.

## How to fix it

**A missing colon.** An `if`, `elif`, `else`, `for`, `while`, `def` or `class` line ends with `:`:

```taipan
let n = 3
if n > 2
    print("big")
```

```error
main.tpn:2:9: error TP0100: expected ':', found newline
  help: end the line with ':'
```

```taipan
let n = 3
if n > 2:
    print("big")
```

```output
big
```

**A bracket that isn't closed.** The compiler keeps reading until it finds something that can't be inside the brackets, so the error points at the next line:

```taipan
let items = [1, 2, 3
print(items)
```

```error
main.tpn:2:1: error TP0100: expected ']', found name 'print'
```

```taipan
let items = [1, 2, 3]
print(items)
```

```output
[1, 2, 3]
```

**Python's `a if c else b`.** Taipan has no conditional expression:

```taipan
let n = 3
let size = "big" if n > 2 else "small"
print(size)
```

```error
main.tpn:2:18: error TP0100: Taipan has no conditional expression
  help: use a 'match' expression or an 'if' statement
```

Use a `match` expression on the condition, or a `var` that an `if` assigns:

```taipan
let n = 3
let size = match n > 2:
    True: "big"
    False: "small"
print(size)
```

```output
big
```

[Control flow](../../language/control-flow/#no-conditional-expression) has more on choosing a value, and [`match` expressions](../../language/match/#match-expressions) on writing one.
