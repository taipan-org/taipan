## What it means

A Taipan project's `taipan.json` lists `references` or `packages`. Outside a project, `taipan run` and `taipan build` read the .NET assemblies and NuGet packages a program uses from `taipan.json`. In a `.tpnproj` project, `dotnet build` gets them from the project file instead, as for any .NET project, so a list in `taipan.json` would be ignored. Rather than silently build without them, the build stops.

This code comes from the build, not the compiler, so `taipan run` and `taipan check` never report it.

## How to fix it

Here, the library project `Geometry/Geometry.tpnproj` has a `taipan.json` beside it that asks for a package:

```json
{
  "packages": { "Humanizer.Core": "2.14.1" }
}
```

```sh
dotnet build
```

```text
/work/Geometry/taipan.json(1,1): error TPN002: list references and packages in the project file, not taipan.json [/work/Geometry/Geometry.tpnproj]
/usr/lib/dotnet/sdk/10.0.114/Microsoft.Common.CurrentVersion.targets(4903,5): error MSB3030: Could not copy the file "obj/Debug/net10.0/Geometry.dll" because it was not found. [/work/Geometry/Geometry.tpnproj]
```

The second error only follows from the first: the library wasn't compiled. Delete the list from `taipan.json` (or the file, if that was all it had), and give the project file a `PackageReference`, or a `ProjectReference` or `Reference` for an assembly:

```xml
<Project Sdk="TaipanLang.Sdk/0.10.1">
  <ItemGroup>
    <PackageReference Include="Humanizer.Core" Version="2.14.1" />
  </ItemGroup>
</Project>
```

```sh
dotnet build
```

```text
  Geometry -> /work/Geometry/bin/Debug/net10.0/Geometry.dll

Build succeeded.
    0 Warning(s)
    0 Error(s)
```

[Projects](../../guides/projects/#a-project) has how a project lists its references.
