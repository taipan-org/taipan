## What it means

A method that overrides a base class's method doesn't fit where the base's method is used. Code written for the base class may be handed a subclass object, and then calls its method instead, so the override must accept every call the base's method accepts and give back the same kind of result. It needs the same parameters, with the same names, order and types, a default wherever the base has one, and the same return type (or, for a class, a subclass of it). Python lets an override differ, and the program fails only when a call that worked on the base doesn't fit.

## How to fix it

`Dog.speak` takes an extra parameter, so `pet.speak()` on an `Animal` that's really a `Dog` couldn't work:

```taipan
class Animal:
    def speak(self) -> str:
        return "..."

class Dog(Animal):
    @override
    def speak(self, times: int) -> str:
        return "woof" * times
```

```error
main.tpn:7:9: error TP0228: 'speak' must take the same parameters as 'Animal.speak'
```

Keep the override's parameters as the base's, and put the extra behavior in a method of its own:

```taipan
class Animal:
    def speak(self) -> str:
        return "..."

class Dog(Animal):
    @override
    def speak(self) -> str:
        return "woof"

    def speak_times(self, times: int) -> str:
        return " ".join([self.speak()] * times)

let pets: list[Animal] = [Animal(), Dog()]
for p in pets:
    print(p.speak())
print(Dog().speak_times(3))
```

```output
...
woof
woof woof woof
```

A different return type is reported the same way:

```taipan
class Animal:
    def speak(self) -> str:
        return "..."

class Dog(Animal):
    @override
    def speak(self) -> None:
        print("woof")
```

```error
main.tpn:7:9: error TP0228: 'speak' must return str, as 'Animal.speak' does
```
