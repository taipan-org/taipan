## What it means

A .NET type or member was used that Taipan can't use, or not in the form written. Taipan maps .NET's common types to its own, `string` to `str`, `long` to `int`, `List<T>` to `list[T]`, and can use most .NET classes directly, but some types have no Taipan form yet, such as `Int128` and `Span<T>`. A method or property that takes or returns one of those can't be called. The message names the type that's the problem.

The same code covers .NET generic types that Taipan has a type of its own for (write `list[int]`, not `List[int]`), and .NET interfaces with a property, event or indexer, which a Taipan class can't implement yet.

## How to fix it

Here, the .NET `List` is used for a list of strings:

```taipan
from dotnet.System.Collections.Generic import List

let names = List[str]()
names.Add("ada")
print(names.Count)
```

```error
main.tpn:3:13: error TP0231: 'List[str]' is list[str] in Taipan; write 'list[str]'
```

Use Taipan's `list`, which .NET code sees as a `List<string>`. Other .NET generic types, such as `Queue`, are used as they are:

```taipan
from dotnet.System.Collections.Generic import Queue

let names: list[str] = []
names.append("ada")
print(len(names))
let waiting = Queue[str]()
waiting.Enqueue("bob")
print(waiting.Count)
```

```output
1
1
```

For a member that uses a type Taipan can't use yet, such as `Int128.Parse`, look for another member or type that does the same with types Taipan has (`int("5")` here). [Types at the boundary](../../guides/dotnet/#types-at-the-boundary) lists how .NET's types map to Taipan's.
