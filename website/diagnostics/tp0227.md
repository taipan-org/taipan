## What it means

A method's `@override` marking doesn't match what it does. In Taipan, a method that replaces a method of its base class must say so with `@override`, and `@override` on a method that replaces nothing is an error too. This catches a misspelled method name, which in Python would quietly add a new method instead of replacing the old one, and a method added to a base class later that would silently take over a subclass's method of the same name. Python's `@typing.override` is optional; in Taipan it's required.

## How to fix it

`speak` replaces `Animal.speak` without saying so, and `fetch` says so but replaces nothing:

```taipan
class Animal:
    def speak(self) -> str:
        return "..."

class Dog(Animal):
    def speak(self) -> str:
        return "woof"

    @override
    def fetch(self) -> str:
        return "ball"
```

```error
main.tpn:6:9: error TP0227: 'speak' overrides 'Animal.speak'; mark it '@override'
  help: write '@override' on the line above it, or rename it if it isn't meant to override
main.tpn:10:9: error TP0227: 'fetch' does not override a method of 'Animal'
  help: remove '@override', or check the name against the base class's methods
```

Put `@override` on the methods that replace a base class's, and only on those:

```taipan
class Animal:
    def speak(self) -> str:
        return "..."

class Dog(Animal):
    @override
    def speak(self) -> str:
        return "woof"

    def fetch(self) -> str:
        return "ball"

let pets: list[Animal] = [Animal(), Dog()]
for p in pets:
    print(p.speak())
```

```output
...
woof
```

If `@override` is on a method you meant to replace, check its name against the base class's. [Classes](../../language/classes/) covers overriding.
